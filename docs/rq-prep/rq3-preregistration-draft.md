# RQ3 事前登記草稿：領域分工辯論（Domain-Specialized Debate）

> **草稿，尚未作為新版正式登記或產出正式結果。** 2026-10-15 更新：Domain Debate Module 與 Final Aggregator 已實作且有合成測試；下方保留舊方案選項與預算。v7 主要比較限定固定立場、每領域另有 View judge（29 呼叫），並要求資源對齊通才、資訊切分不辯論兩項對照；舊 V=0 與 optional control 建議不能直接作正式方案。`views` 實際仍提供 View 引用的 evidence 與基準率，全無引用時會退回全證據，須納入新版規則。見 [修正進度](../review/remediation-status-2026-10-15.md)。正式登記後只追加偏離說明。

## 研究問題

> 相較於將四類金融資訊整合後交由共同多空代理人辯論，若改由技術面、基本面、情緒面與總經面代理人分別在各自資訊領域進行多空辯論，再由上層整合機制形成最終投資決策，是否能改善方向準確率與風險調整後績效？

估計量：在同樣的資料、模型、期間、輸出格式與守門員之下，「四領域辯論＋上層整合」相對 Generalist 辯論的整套架構差。除非計算量也一起匹配，否則不能稱為純分工效果（Part-C 第 7、8 項）。

## 實驗組（草稿）

| 組 | 內容 | 每案決策呼叫 |
|---|---|---|
| G_C（Generalist 固定立場） | 與 RQ1 的 C 相同 | 7 |
| G_D（Generalist 立場交換） | 與 RQ1 的 D 相同 | 7 |
| Dom_C | 四領域各自進行固定立場辯論，Bull/Bear × 3 輪 → Domain View → Aggregator | 24＋V＋1 |
| Dom_D | 四領域各自進行立場交換辯論（第 2 輪自我反駁） → Domain View → Aggregator | 24＋V＋1 |

V＝Domain View 生成所需的呼叫數：用程式從第 3 輪輸出組成時 V＝0，每個領域另用一次 LLM 摘要時 V＝4。

公平比較的原則：Dom_C 對 G_C、Dom_D 對 G_D。不能拿 G_C 對 Dom_D，再稱之為分工效果。

## Domain View 與 Aggregator（草稿）

- **Domain View 結構**【待鎖定】：`domain`、`stance`（Buy／Sell／abstain）、`expected_return_pct`、`confidence`、支持證據 ID、反證 ID、不確定性、資訊缺口；理由長度上限與 RQ1 相同（600 字）。
- **缺資料／無方向**：可以輸出 abstain，並另外記錄。4:0、3:1、2:2 只針對四個有效的二元立場計算，abstain 不能塞進 2:2。
- **Aggregator 的輸入**【待鎖定】：建議只讀四個 View，順序固定為技術→基本→情緒→總經，不讀完整逐字稿；記憶規則與 RQ1 的裁決者相同。輸出必須在買進與賣出之間擇一（與 RQ1 的 C/D 裁決者一致）。
- 四個 View 是同一案的中間產物，不是四筆獨立樣本，回測只建一個部位。

## 分析計畫（草稿）

1. **主要比較**【待鎖定】：建議 Dom_X 對 G_X，其中 X 是事先選定的辯論規則（見決策 1）。共同主要端點為 60 日方向準確率（配對 McNemar）與 Sharpe 差（Ledoit–Wolf），兩個端點做 Holm 校正，都為正且顯著才判定改善。
2. **資源報告**（必報，不作為排除條件）：每案的呼叫數、重試、輸入／輸出 tokens、推理秒數、端到端延遲；畫出績效對成本的前緣。
3. **次要／診斷**：四個領域的立場分布、一致程度（4:0／3:1／2:2／含 abstain）、Aggregator 跟隨多數的比例、少數領域勝出的案例、各領域單獨方向的準確率（僅供描述）。
4. **敏感性**：30、90 日；不計成本；守門員後；排除 37 個低新聞量案例；排除情緒領域 abstain 的案例。
5. **依賴性**：日期群聚與區塊重抽樣，與 RQ1 相同；20 個日期群聚數量有限，結果需審慎解讀。

## 已知限制（執行前）

- 呼叫數相同，不代表 tokens 與計算量相同。領域辯論的 context 較短，但呼叫數多很多。
- 把資訊切成四個領域，可能失去跨領域的交互作用（例如財報與新聞彼此印證）。
- Aggregator 會受輸入順序、長度與文風影響。
- 同一批 180 案已在 RQ1 看過，這裡同樣屬於回溯比較。
- 基本面目前是程式化的 `source_locked_comparative`（不呼叫模型），基本面領域辯論能用的證據只有約 4 項；MCD 2023-12-31 沒有情緒指標。

## 呼叫與 GPU 時間預算（估計）

基準：E2′ 實測約 22 案／小時，每案約 2.7 分鐘（22 次決策呼叫，一張 RTX 5090，US$0.75／小時），約 **7.4 秒／呼叫**。領域辯論的 prompt 較短，實際時間可能較少，下表可視為上限。表中的數字不含 Generalist 組。

| 領域規則 | View 生成 | 每案呼叫（辯論＋View＋Aggregator） | 每案時間 | 180 案 | GPU 費用 |
|---|---|---:|---:|---:|---:|
| 只跑固定立場 | 程式（V＝0） | 24＋0＋1＝25 | 約 3.1 分 | 約 9.3 小時 | 約 US$7.0 |
| 只跑固定立場 | LLM（V＝4） | 24＋4＋1＝29 | 約 3.6 分 | 約 10.7 小時 | 約 US$8.0 |
| 只跑立場交換 | V＝0／4 | 25／29 | 3.1／3.6 分 | 9.3／10.7 小時 | US$7.0／8.0 |
| 兩者都跑 | V＝0 | 2×25＝50 | 約 6.2 分 | 約 18.5 小時 | 約 US$13.9 |
| 兩者都跑 | V＝4 | 2×29＝58 | 約 7.2 分 | 約 21.5 小時 | 約 US$16.1 |
| 低預算（每域 1 輪，敏感性） | V＝0 | 8＋0＋1＝9 | 約 1.1 分 | 約 3.3 小時 | 約 US$2.5 |

- Generalist 若在 RQ3 協議內重跑，C＋D 每案 +14 次呼叫，約 +5.2 小時、+US$3.9；只跑一種規則時 +7 次呼叫，約 +2.6 小時、+US$1.9。
- 建議方案（固定立場、V＝0、重跑 G_C、加低預算敏感性）：每案 25＋7＋9＝41 次呼叫，約 5.1 分鐘；180 案約 15.2 小時、約 US$11.4。
- 執行前用 3–5 案的 canary 實測每次呼叫的秒數與 tokens，再更新預算。
