## F1：完整數字事實，而不是任選數字片段

新版要求含數字的事實句為獨立句子，格式如下；句尾可有句點，其他推論仍能使用不含數字的自然語言：

```text
Revenue [2024-12-31] = 100 USD.
```

對應的 `numeric_claims` 綁定已引用證據的 `evidence_id`、`metric`、`period`、`unit`、`value`，`quote` 必須為完整句子。來源欄位完全匹配，數值須為原值、三位有效數字的半向上四捨五入，或按所寫小數位半向上四捨五入；非零來源不可因此變成零。

驗證引用在各文字欄位中的實際位置，且逐次核對重複出現的句子。不存在於某欄位的 quote 不再覆蓋該欄位的數字。以下反例都有回歸測試：

- `Revenue was 100 billion USD.` 或 `Net income was 100 USD.`，但 quote 只填 `100`。
- 完整敘述或固定句型把 USD 改成 EUR、變更指標或期間。
- 合法句子前後附加重新解釋其指標／尺度的文字。
- rationale 引用合法事實，risks 另寫未支持的同值數字。
- 以模型自己的 `expected_return_pct=5` 支持「營收 5」，但來源營收為 100。
- 把 2000 USD 當成年份而跳過驗證。

合法來源事實、重複／跨欄位的合法引用、負值四捨五入、百分比與非財務單位、含窗口數字的來源指標及跨期標籤亦有正向測試。立即移除無效數字的政策保留，並記錄主張移除數及欄位；這不表示原決策未受錯誤事實影響，仍需品質分層分析。

修改檔案：`research_service/models.py`、`engine.py`、`protocol.py`。

## F2：執行權與世代編號共同隔離寫入

工作增加 `lease_generation`（舊資料庫自動遷移為 0）。每次取得租約或復原孤兒工作增加世代；背景 worker 的成功及失敗保存都帶入取得時的 owner／generation，在 SQLite 寫入交易內核對。失配直接拋出 `JobLeaseLost`，app 丟棄過期輸出，不再用它保存錯誤或索引結果。

- 暫停／取消會立即呈現控制狀態，但仍在呼叫中的 owner 保留至檢查點；不能被其他 worker 或 CLI 直接接管。
- 呼叫中續跑由原 worker 保存後回到 queued，每步釋放 owner；未改成 CLI 的永久 running 流程。
- 已死 worker 的 paused／cancelled 租約也能復原；活服務不會被復原，舊版 owner 空白的 running 工作仍能復原。
- 復原後其他 worker 或 CLI 可以接管，舊 worker 的正常／失敗輸出都不能覆寫。
- 同一 worker 身分重取租約，也以 generation 拒絕上一世代的輸出。
- 取消中的最後一步不寫入 `case_results`；仍在呼叫中的暫停／取消工作會計入 active count，避免過早啟動 GPU 閒置倒數。
- 控制及檢查點交易串行，避免 pause/resume 依過期狀態作判斷。

修改檔案：`research_service/storage.py`、`app.py`。
