# 實驗架構：三組獨立實驗

研究問題與實驗的對應（見 `report/stance-shift-ssrn.tex`）：

| 研究問題 | 內容 | 由哪個實驗回答 |
|---|---|---|
| RQ1 | 同一模型內比較 A／B／C／D（核心為 D 對 C） | E2（已完成）；E1 補齊後同樣回答 |
| RQ2 | 跨時間尺度：以季 vs 以月為分析單位 | E3（待做）對照 E2 |
| RQ3 | 跨模型：RQ1 的結果在不同模型間是否一致 | E1 對照 E2；記憶汙染檢驗為其補充分析 |

## 原則

**一個實驗 ＝ 一個協議版本 ＝ 一個映像 ＝ 一個資料庫 ＝ 一個連接埠。**

不同協議版本的服務不可共用同一個資料庫：服務只執行自己版本的工作，會把其他版本的排隊工作標為「舊版實驗已隔離」並暫停。共用資料庫時，兩個服務會互相暫停對方的批次，這是 2026-09-28 實際發生過的問題。各實驗獨立資料庫、各自固定映像後，可以同時進行。

## 決定：跨模型對照組須與 qwen3:32b 相近

原則（2026-09-29）：RQ3 的對照模型**不可與 qwen3:32b 差距過大**。RQ3 要看的是「結果記憶」是否改變 RQ1 的結論；若對照模型在能力層級或推理設定上與 qwen3:32b 差很多，差異就無法歸因於記憶。

因此 Gemini 3.1 Pro（旗艦模型、無法關閉思考、需多給 2048 token）**不作為 RQ3 的主要對照**：

| | Gemini 3.1 Pro | Flash 級 |
|---|---|---|
| 能力層級 | 旗艦，與 qwen3:32b 差距大 | 中小型，較接近 |
| 思考設定 | 無法關閉，與 Ollama 上的 qwen3 不一致 | 關閉思考，與 qwen3 一致 |
| 補齊 167 個案例 | 每日 250 次額度，約 18 天 | 額度通常高得多 |
| 費用 | 約 US$0.15／案例，2027-01-01 起加倍 | 較低 |

作法：

1. 對照組改用 Flash 級 Gemini 模型（確切型號、官方知識截止日與每日額度需另行查證後填入）。
2. **與 E2 使用同一協議版本 v3-0929.1**（即映像 `stance-shift-lab-research-qwen:v3-0929.1`），使兩個實驗只差在模型，數字驗證的處理方式也一致。這需要新的 protocol hash 與新的事前登記，並使用獨立資料庫與連接埠（預計 8003），建立時新增對應的 compose 檔。
3. 先對該 Flash 模型執行 `scripts/memory_probe.py`（recall 與 identify 兩種模式）確認它**是否有結果記憶**；若沒有，它無法作為「有記憶」的對照，需再選其他相近但有記憶的模型。
4. Pro 已完成的 13 個案例（v3-0927.2）保留為探索性資料，不再補齊；`compose.gemini.yaml` 保留作為這批資料的封存與檢視入口。

## E3 月度實驗的協議定義

由 E2 的季度設計按比例縮放，只改變分析頻率與其必要的連動項目，其餘（四組決策機制、呼叫預算、提示詞架構、統計方法）不變，使 RQ2 的差異盡量只來自時間尺度。

| 項目 | E2 季度 | E3 月度 |
|---|---|---|
| 分析日 | 2021–2025 季末，20 個 | 2021-01 至 2025-12 月底，60 個 |
| 主要預測期間 | 60 個交易日（約一季） | 20 個交易日（約一個月），相鄰案例不重疊 |
| 穩健性期間 | 30、90 | 10、30 |
| 新聞窗口 | 分析日前 90 天 | 分析日前 30 天（相鄰案例不重疊） |
| 中性帶 | 該股歷史 60 日報酬標準差的一半 | 歷史 20 日報酬標準差的一半 |
| 資料切分 | 2021–2023 訓練、2024 驗證、2025 測試 | 同左 |
| 其餘 | — | 相同：7 次呼叫預算、匿名化選項、事前登記、區塊自助法 |

注意事項：

- 月度案例的基本面證據多數月份沿用同一份季報，這與季度設計不同，屬預期行為。
- E2 與 E3 的案例、新聞窗口與預測期間皆不同，無法逐案配對；RQ2 比較兩種設計下的效果大小與信賴區間，以及組別排序是否一致。
- 案例數 540 使檢定力顯著提高；若 Gemini 知識截止日為 2025-01，截止日後案例由 36 個增至約 108 個。
- 事前登記於 E3 資料庫建立後、任何案例執行前完成，並在報告中寫明。

## E3 前置工作

### 1. 新聞資料（最大風險）

本機新聞檔對月底窗口的涵蓋很不完整（以 9 檔 × 60 月底檢查）：

- Alpha Vantage 快取自 2023-12 起；FNSPID 對 GOOGL、JPM、MCD 只到 2020-06，AAPL、AMZN 到 2023-12。
- 60 個月底中，任何窗口內都沒有本機新聞者：AAPL 17、NVDA 7、GOOGL 35、MSFT 15、AMZN 26、JPM 35、MCD 35、INTC 0、GE 0，合計 170／540。
- E2 的 180 個季度資料集沒有這個問題，因為 2021–2023 的新聞是建立資料集時由 Alpha Vantage 即時 API 取得（180 個資料集皆有情緒證據）。

因此 2021-01 至 2023-11 需要重新以 Alpha Vantage 取得 30 天窗口的新聞，約 35 個月 × 9 檔 ＝ 315 次請求，可沿用 `research-inputs/av_checkpoint.json` 的以「檔 × 月」為單位的更新機制。需確認 API 方案的每日額度與是否為付費方案。

### 2. 程式碼修改（新協議版本，於獨立分支實作）

- `protocol.py`：主要預測期間與穩健性期間改為可依協議設定（目前第 96–97 行強制 60 與 30／60／90）；新增月底分析日集合與 `validate_case` 規則（目前只接受 `QUARTER_DATES`）；新版本號與允許版本清單。
- `data.py`：新聞回看窗口目前寫死 90 天（第 188、207、251、302 行與多處提示文字），改為資料集收集規則的參數並記錄於 `collection_rules`。
- 使用 `QUARTER_DATES` 的地方：`readiness.py`、`splits.py`、`cli.py`、`interactive.py`、`web/system.py`。
- `reporting.py`：多處預設或比較條件寫死 `horizon == 60`（第 366、392、482、686 行），改為讀協議的 `primary_horizon`。
- `knowledge.py`：`knowledge_segment` 與 `split_by_knowledge` 的預設期間 60。
- 提示詞與中性帶中與 60 日相關的說明文字、測試、文件。

### 3. 執行順序

1. 選定 Flash 級對照模型並做記憶測試；通過後建立 Flash 對照組的 compose、預先登記並補齊。
2. 於獨立分支實作月度協議，測試通過後固定映像標籤。
3. 補齊 2021-01 至 2023-11 的 30 天新聞；建立 540 個資料集。
4. 於 E3 資料庫預先登記 540 個案例。
5. 租用 RTX 5090，部署 Ollama 並載入 qwen3:32b（模型檔已保存在 `/vault/ollama/models`），跑 canary，再開始。預估約 18 小時、US$14。
6. 完成後停止 GPU 執行個體。

Flash 對照組的補齊與 E3 使用不同的算力（Gemini API 與 GPU）與不同的資料庫，可同步進行。
