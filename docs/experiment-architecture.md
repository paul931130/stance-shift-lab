| RQ1 | 同一模型、同一新版協議內比較 A／B／C／D；D−C 是「交換立場＋交換輪只看自身歷史」的整套機制效果，不是純立場互換效果 | 先重跑新版季度 180 案（v3-0930.3） |

## 資料庫與映像隔離

**一個實驗版本／模型身分 ＝ 一個固定映像 ＝ 一個獨立資料庫 ＝ 一個連接埠。** 已知曾發生共用資料庫令服務互相暫停批次的問題；新批次建立前需各自凍結輸入快照、映像摘要、protocol hash 與事前登記。舊版容器與資料庫只讀保存，不重建覆寫。

| 批次 | Compose | 連接埠 | 資料庫 volume | 建議處理 |
|---|---|---:|---|---|
| Gemini Pro 舊版 | `experiments/e1-gemini.yaml` | 8000 | `stance-shift-lab_research-data` | 僅封存／檢視；不得載入新協議 |
| Qwen 舊版 | `experiments/e2-qwen.yaml` | 8001 | `stance-shift-lab_research-data-qwen` | 唯讀封存 |
| Qwen 新版季度 | 新增固定版映像與獨立 DB | 未分配 | 新建 | 先執行 |
| Gemini Flash 新版季度 | 固定模型身分與獨立 DB | 未分配 | 新建 | Qwen 季度與月度分析後配對重跑 |
| Qwen 月度 | `experiments/e3-monthly.yaml` | 8002 | `stance-shift-lab_research-data-monthly` | 季度報告完成後執行；映像需固定版本 |

季度新版共同設定：FinBERT 窗口內全量指標、至少 3 則已評分標題才產生指標、相同證據快照、v3-0930.3 數字主張驗證、同一提示與推理政策（Flash 關閉思考；Qwen `think: false`）、溫度／取樣與輸出上限完全一致。模型不同使 protocol hash 必然不同；不得直接合併兩份 `study_report`，須按 ticker × 日期 × dataset ID 配對，再由專用跨模型分析呈現。

Gemini 3.1 Pro 的 13 案與 Qwen 舊版完整資料各自保留，不用於新版模型差異估計。Flash alias 可能隨供應商變動；執行前須記錄並確認 resolved model identity、推理設定與限制，並先跑一案 canary；若身分無法固定或驗證政策與 Qwen 不一致，暫停 RQ3，不以模型名稱字串假設等價。

## 新版季度 → 月度（RQ2）的協議定義

由新版季度 v3-0930.3 按比例縮放，只改變分析頻率與其必要的連動項目，其餘四組決策機制、呼叫預算、提示詞、FinBERT 規則與數字主張驗證政策不變，使 RQ2 的差異盡量只來自時間尺度。月度協議為 v3-0930.4；舊版 Qwen v3-0929.1 不作新版季度基準。

| 項目 | 新版季度基準 | E3 月度 |
|---|---|---|
| 分析日 | 2021–2025 季末，20 個 | 2021-01 至 2025-12 月底，60 個 |
| 主要預測期間 | 60 個交易日（約一季） | 20 個交易日（約一個月），相鄰案例幾乎不重疊，短月份至多重疊一至兩個交易日 |
| 穩健性期間 | 30、90 | 10、30 |
| 新聞窗口 | 分析日前 90 天 | 分析日前 30 天（相鄰案例幾乎不重疊，短月份至多重疊一至兩個交易日） |
| 中性帶 | 該股歷史 60 日報酬標準差的一半 | 歷史 20 日報酬標準差的一半 |
| 資料切分 | 2021–2023 訓練、2024 驗證、2025 測試 | 同左 |
| 其餘 | — | 相同：7 次呼叫預算、匿名化選項、事前登記、區塊自助法 |

注意事項：

- 月度案例的基本面證據多數月份沿用同一份季報，這與季度設計不同，屬預期行為。
- 季度與月度案例、新聞窗口與預測期間不同，無法逐案配對；RQ2 比較兩種設計下的效果大小與信賴區間，以及組別排序是否一致。
- 月度樣本 540 案增加時間覆蓋，但有效檢定力仍受日期群聚、股票相依與缺失資料限制；若跨模型方案涉及知識截止日，須在執行前核對該模型並分段報告，不預設截止日期或樣本必然足夠。
- 事前登記於 E3 資料庫建立後、任何案例執行前完成，並在報告中寫明。

## E3 前置工作

### 1. 新聞資料（最大風險）

本機新聞檔對月底窗口的涵蓋很不完整（以 9 檔 × 60 月底檢查）：

- Alpha Vantage 快取自 2023-12 起；FNSPID 對 GOOGL、JPM、MCD 只到 2020-06，AAPL、AMZN 到 2023-12。
- 60 個月底中，任何窗口內都沒有本機新聞者：AAPL 17、NVDA 7、GOOGL 35、MSFT 15、AMZN 26、JPM 35、MCD 35、INTC 0、GE 0，合計 170／540。
- E2 的 180 個季度資料集沒有這個問題，因為 2021–2023 的新聞是建立資料集時由 Alpha Vantage 即時 API 取得（180 個資料集皆有情緒證據）。

可直接重用已下載的資料，不必全部重抓（2026-09-29 重新計算，含當天補抓的 2021-01、2021-02）：

- 540 個月底 30 天窗口中，**384 個**已被本機新聞檔（FNSPID＋Alpha Vantage 快取）涵蓋，直接使用。
- 其餘 **156 個**（103＋53）本機新聞檔沒有。這些期間的新聞其實已存在 E2 的 180 個季度資料集裡：各季 90 天窗口首尾相接，每個月底窗口都落在某個資料集的窗口內；其中 125 個至少有 1 筆（中位數 14.5 筆），31 個完全沒有。但資料集當時是「每來源最多 50 筆」，180 個資料集中 146 個已達上限，等於整季只留了相關度最高的 50 筆，每個月分到的很少且有偏。
- 因此有兩種作法：（A）由資料集匯入（0 次請求），但證據密度與本機新聞檔涵蓋的 384 個窗口不一致，且 31 個仍需抓取；（B）對這 156 個「檔×月」重新抓取（免費金鑰每日 25 次，約 6–7 天），540 個窗口的建立方式一致。抓取不是瓶頸（E1 補齊需約 18 天），建議 B。
採用 B 時，只針對這 156 個「檔×月」呼叫 Alpha Vantage。內建的 `refresh_archive` 會抓取範圍內所有尚未完成的「檔×月」（共 297 個），不會略過已被涵蓋者，因此改用只抓缺口的清單。

### 2. 程式碼修改（已完成於目前工作目錄）

以「設計」欄位讓同一份程式同時支援季度與月度；新版驗證規則改變，因此新版 protocol hash 必須更新：

- `protocol.py`：`design`、`StudyProtocol.monthly()`、`MONTH_END_DATES`、`DESIGNS`、`protocol_is_current`；`cases()` 與 `validate_case()` 依設計取分析日。
- `data.py`／`collect.py`：新聞窗口參數 `window_days`；月度資料集在 `collection_rules` 記錄設計與窗口，並與季度快照分開重用。
- `web/jobs.py`、`web/context.py`、`web/datasets.py`、`api.py`：`design` 欄位、設計不符檢查、批次上限 600。
- `readiness.py`、`splits.py`、`reporting.py`、`knowledge.py`、`models.py`：依設計取主要期間、穩健性期間、基準率窗口與結果期間。
- 尚未涵蓋：網頁介面、CLI 與互動模式（僅季度）；月度實驗以 API 執行。

### 3. 執行順序

1. 固定新版季度映像、輸入資料規則與 180 案資料集 ID；先做 canary 與品質檢查，再事前登記。
2. 以 qwen3:32b 完成新版季度 180 案；舊版 180 案不可抵扣此樣本數。
3. 匯總新聞來源／缺失率、數字驗證品質分層、日期群聚區間及 Train／Validation／Test，確認工作完成、品質通過與正式樣本完整三者分開。
4. 新版季度對照及品質／完整度報告完成後，才建立／凍結 540 個月度資料集與事前登記，執行 v3-0930.4。
5. 新版 Qwen 季度與月度分析完成後，再以相同季度資料集 ID 和 v3-0930.3 規則執行 Flash 配對跨模型批次；兩模型分開資料庫，按案例 ID 另作比較。
6. GPUtw 5090 的租用費與耗時是會變動的外部值；執行前重新核對即時價格、額度、模型檔與執行個體狀態。舊版預估不得當作本輪報價。
