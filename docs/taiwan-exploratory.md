# 台股探索：行情、代理報告與模擬決策

第一版在現有研究服務中提供獨立的 `/taiwan` 頁面。選擇台股、讀取行情、產生多頭／空頭／裁判報告，最後由使用者記錄模擬方向與股數。這是探索功能，不是 RQ1／RQ2／RQ3 正式實驗，也不執行券商委託。

## 啟動與操作

在專案根目錄啟動既有服務：

```powershell
.\.venv\Scripts\python.exe -m uvicorn research_service.app:create_app --factory --host 127.0.0.1 --port 8000
```

開啟 `http://127.0.0.1:8000/taiwan`，或由研究室首頁進入「台股探索」。若有存取金鑰，使用同一組金鑰登入。模型沿用既有研究室設定（本機 Ollama 或已設定的供應商）；使用雲端模型仍會依供應商計費。

1. 選擇股票或輸入 Yahoo 台股代碼，例如上市 `2330.TW`、上櫃 `6488.TWO`。
2. 讀取行情，確認來源與行情日期。
3. 選擇模型並產生報告，等待多頭、空頭與裁判完成。
4. 閱讀雙方理由與缺資料限制，再自行選擇 Buy／Hold／Sell、輸入股數與備註。
5. 儲存模擬決策。紀錄使用報告建立時的價格快照，不是即時成交價；不計手續費、稅或滑價，也不代表委託或成交。

## 第一版資料範圍

- 行情透過現有 `yfinance` 依賴取得 Yahoo 日線，屬延遲資料；沒有 SSE 盤中串流。
- 尚未串接 Shioaji server、券商帳戶、CA 或下單端點，也沒有複製 Shioaji Pro 的原始碼。
- 尚未接入台灣財報、中文新聞、籌碼與總經資料。報告必須揭露缺資料，不能把價格分析描述成完整四領域研究。
- 多頭、空頭與裁判沿用既有模型呼叫與結構化輸出工具，但使用獨立探索提示，沒有宣稱完成原研究協議的四組比較或立場交換實驗。
- 合成展示模式不可用假模型產生貌似真實台股研究報告。真實行情或模型失敗會顯示錯誤，不自動改用假資料。

## 儲存與隔離

台股報告、模型呼叫紀錄、行情快照與模擬決策儲存在 `RESEARCH_DATA_DIR` 下獨立的 `taiwan-exploratory.sqlite3`。不建立正式研究 jobs、不加入正式資料集、不計入研究績效。備份台股探索資料時，需另外備份此資料庫；既有正式研究匯出不代表包含這些紀錄。

這次功能修改仍會改變程式來源；後續正式實驗應重新產生來源指紋與依既有操作單進行資格確認，不沿用舊版程式封存作為新版驗證。

## 共用資料目錄與中斷恢復

- 每個服務有獨立擁有者識別，每十五秒更新心跳。啟動另一個服務不會將仍由活躍服務處理的報告標成失敗。
- 共用同一資料目錄時，相同股票與模型的未完成報告只能有一份，所有服務合計最多三份排隊或執行中的報告；檢查與建立使用同一筆 SQLite 交易。
- 心跳超過九十秒未更新的服務，其未完成報告會在恢復檢查時標記失敗；正常關閉只中止該服務自己的未完成報告。舊版沒有擁有者的未完成報告也會標記失敗，已完成報告與模擬決策保留。
- 失敗工作不會自動重送模型，需自行重新建立。已送出的模型請求仍可能在供應商端完成，但關閉或失聯後回傳的結果不能覆寫報告，也不再繼續後續角色。
- 更新到本版本前應先停止舊服務，避免沒有擁有者管理的舊版程序繼續寫入共用資料庫。

## 後續 Shioaji 接點

保留目前「行情提供者 → 鎖定快照 → 多代理人報告 → 模擬決策」邊界。下一階段以 Shioaji HTTP 行情提供者取代 Yahoo 日線，新增連線設定、行情時間與斷線狀態；報告與模擬決策仍使用固定快照。Shioaji Pro 前端面板整合與真實帳戶連線需另外實作驗收。
