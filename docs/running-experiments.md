# 跑正式實驗

這份文件說明怎麼把一整批事前登記的案例跑完，而且不浪費 GPU 時間。單一案例的試跑用 CLI 即可（見 README）。

## 名詞

| 名詞 | 意思 |
|---|---|
| 協議（protocol） | 一套固定的研究規則：提示詞、模型、溫度、驗證規則等。任何一項改變都會產生新的 protocol hash |
| 資料集（dataset） | 一個股票 × 分析日的資料快照，建立後內容以雜湊鎖定 |
| 事前登記（preregistration） | 在執行任何案例前，鎖定「這個協議要跑哪些資料集」。登記後不能增減；登記後才建立的工作才算正式結果 |
| 批次檔 | `{"cases": [{"dataset_id": "...", "analysis_date": "...", "model": "..."}]}`，每筆一個案例 |

## 流程

```text
建立資料集 → 事前登記（鎖樣本）→ 開 GPU → 排入批次 → 看進度 → 自動關機 → 看統計
```

### 1. 事前登記

在網頁「建立實驗 → 批次研究」匯入批次檔並勾選「先鎖定這批研究樣本」，或用 API：

```bash
curl -X POST http://127.0.0.1:8000/api/studies/preregister -H "Content-Type: application/json" --data-binary @cases.json
```

登記時會用與正式執行完全相同的規則檢查每一案（資料品質、模型是否可用），所以**模型端點必須連得上**。回傳的 `protocol_hash` 就是這個研究的 ID。另外寫一份文件記錄資料來源、缺口處理與分析計畫，在執行前提交（範例：[E2′ 事前登記](e2prime-preregistration.md)）。

### 2. 開 GPU

照 [GPUtw 雲端 GPU](gputw-integration.md) 開機，等約 10 分鐘模型載入。網頁右上角的模型狀態變綠即可。

### 3. 排入

網頁最上方「正式實驗」卡 →「排入批次檔…」→ 選同一份批次檔。或：

```bash
curl -X POST http://127.0.0.1:8000/api/studies/<protocol_hash>/enqueue -H "Content-Type: application/json" --data-binary @cases.json
```

- **可以重複送**：已經有工作的案例會略過，不會重複跑。
- 不在登記樣本內、或協議不同（例如改了投票次數）的案例會整批拒絕，一案都不會排入。
- 案例依分析日由早到晚執行：每個案例會參考同一協議、同一股票中較早且已到期的結果（記憶），所以順序固定。

### 4. 看進度

「正式實驗」卡每幾秒更新：完成數、執行中、等待、暫停、錯誤清單，以及依最近一小時產能估算的剩餘時間。也可以用 `GET /api/studies/<protocol_hash>/progress`。

案例出錯（例如模型逾時）會自動暫停並列在錯誤清單。處理完原因後按「全部繼續」，完成的步驟都保留，不會重跑。

### 5. 關機

設定了 `GPUTW_MANAGE_API_KEY` 時，佇列沒有等待或執行中的案例超過 15 分鐘（`RESEARCH_GPUTW_AUTOSTOP_MINUTES`），研究台會停止 GPUtw 機器。所有案例都出錯暫停時也算佇列清空，所以卡住的批次不會一直燒錢。沒有設定時請自己在 GPUtw 控制台停止。

### 6. 看結果

在佇列選一個已完成的案例，進入「統計結果」：四組比較、各期間的檢定、日期群聚、知識截止日分段、數字修補的品質分層與新聞覆蓋，可下載 `summary.csv` 與完整 JSON。

## 速度與可重現性

GPU 上的 Ollama 預設一次處理一個呼叫（`RESEARCH_OLLAMA_PARALLEL=1`）。RTX 5090 上 qwen3:32b 季度 180 案約 6.5 小時。

設成 `4`（Ollama 需 `OLLAMA_NUM_PARALLEL=4`）約快 2.1 倍。以 32 個真實提示詞實測：

| 比較 | 決策相同 | 預期報酬相同 | 文字逐字相同 |
|---|---|---|---|
| 逐一 vs 再逐一一次 | 32/32 | 31/32 | 25/32 |
| 逐一 vs 4 個同時 | 31/32 | 26/32 | 5/32 |

同時處理不會偏向哪一組，但結果不會與逐一處理逐字相同。需要與既有逐一處理的實驗比對時維持 `1`；新開的實驗可以用 `4`，並在論文中註明。

## 常見狀況

| 看到 | 原因與處理 |
|---|---|
| 「遠端 GPU（GPUtw）目前連不上」 | 機器關機或還在載入模型。開機後等 10 分鐘再按「更新狀態」 |
| 「研究樣本已於 … 鎖定，不能再變更」 | 這個協議已登記過另一批樣本。要換樣本就需要新的協議版本 |
| 「舊版協議：只能查看」 | 程式升級後協議版本改變，舊工作不能用新引擎續跑；結果保留 |
| 排入時「協議與登記不符」 | 批次檔的設定（模型、投票次數、缺資料策略等）和登記時不同 |
| 自動關機未啟用 | 沒有設定 `GPUTW_MANAGE_API_KEY` 或 `GPUTW_INSTANCE_ID` |
